OPC Data eXchange Sample Code

August 19, 2003

Overview

The latest version of this document always on the OPC foundation website.

Any use of the OPC Data eXchange Sample Code is subject to the terms the OPC Foundation License Agreement.

The OPC Data eXchange Sample Code consists of an C# client application and a C++ server application. These applications implement the Data eXchange Interface Specification 1.00. These samples are intended to demonstrate the correct operation of the specification and to serve as starting point for vendors who wish to develop their own implementations.

The sample client is written completely with .NET technologies; as a result, it also demonstrates how to build .NET applications that interoperate with existing OPC compliant COM servers. Part of the sample client includes some higher-level .NET classes that hide the details of .NET-COM interoperability from the application developer. These classes will be superceded by the Unified Data Access .NET Interface initiative which combines access to XML-DA and COM-DA servers into a single set of .NET interfaces.

System Requirements

Operating Systems

All source code provided by the OPC Foundation is only supported on Windows 2000 SP3 and Windows XP SP1. That said; the source code has been designed to be portable to other operating systems. For this reason vendors are encouraged to report fixes required to port the samples to other operating systems so they can be incorporated into the baseline and to improve the portability of future sample code.

All .NET components require that the .NET Framework Redistributable 1.1 or the .NET Framework SDK Version 1.1 is present on the target system. The .NET framework does not support Windows 95. All previously released OPC foundation binaries that require the .NET Framework 1.0 will run on systems with only the .NET Framework 1.1 installed. For this reason, users of OPC sample code should never need to install .NET Framework 1.0 on a machine.

All C++/COM applications are compiled as UNICODE applications and will not run on Windows 98 or Windows ME unless they are recompiled. 

Installers

The installer packages are self-installing files; however, they require that Windows Installer 2.0 be present on the system (it is standard on Windows 2000 SP3 and Windows XP). The Windows Installer 2.0 support files for other operating systems can be downloaded from Microsoft's website at:

Download Windows Installer 2.0 Redistributable for Windows NT 4.0 and 2000  

Download Windows Installer 2.0 Redistributable for Windows 95, 98 and ME

Source Code

All source code projects require Visual Studio .NET 2003. 

Visual Studio .NET 2003 can be installed along side both Visual Studio .NET 2002 and Visual Studio 6.0. Existing projects for older development environments do not need to be upgraded in order to use sample code distributed by the OPC Foundation.

Usage

Server

The sample server opens and reads two XML files that must be located in the same directory as itself. The XML files must have the same base name as the server (i.e. 'OpcDxServer'). When executed, the server parses the 'device.xml' file a constructs its DA address space from the items defined within it. The server these parses the 'config.xml' and initializes the DX configuration from its contents.

Client

The sample client can be started from the programs menu. By default, it will connect to the sample server when the ‘connect’ button is clicked. The sample server comes with a standard configuration file that contains two source servers and four connections. When the client connects the source servers should start automatically and the DX target items should immediately start receiving updates. 

The client displays the the DX server configuration in the left hand tree view. The configuration can be modified by right clicking on a node in this view and selecting and operation.

Problem Reporting

As part of a broader initiative to increase adoption of OPC specifications and to improve service to members, the OPC Foundation intends to maintain binaries and sample code over time following a model similar to Open Source projects. Vendors are encouraged to report problems, bug fixes, enhancements and any other comments about the components supplied by the OPC Foundation. To support this effort, the OPC Foundation has technical staff prepared to review and incorporate feedback into the baseline and release new versions of the components and sample code in a timely manner for the benefit of all members.

Please note that this support is intended for OPC Foundation members who are incorporating OPC support into their products.

Problems related to a particular download should be posted to the appropriate group on the OPC Foundation Message Board.
