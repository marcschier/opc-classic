## Conclusion

The OPC AE 1.10 managed implementation in `opc-classic` has a **strong foundation** with complete struct codec support and correct modeling of core server-status and condition-state structures. However, **critical gaps exist in DCOM method declarations**:

1. **Opnum mismatch epidemic** — 10 methods have wrong opnums due to missing QueryEventCategories (opnum 6), QueryEventAttributes (opnum 10), and not accounting for derived-interface inheritance (IOPCEventServer2 starts at 19, not 16). This is a **BLOCKER** that will cause wire-protocol incompatibility with OPC Foundation CTT and third-party clients.

2. **Missing subscription object creation** — `IOPCEventServer::CreateEventSubscription` (opnum 4) is not declared because it returns a COM interface pointer (requires generator extension). This is a **BLOCKER** preventing any subscription-based event monitoring.

3. **Deferred multi-out methods** — 4 HIGH-severity methods (`GetFilter`, `GetState`, `SetState`, subscription state mgmt + IOPCEventServer2 enable-state queries) are commented as "deferred until multi-out records are registered." Post-M5 generator work claims multi-out support exists; these should be unblocked.

4. **Test coverage is narrow** — Integration tests exist for interface IDs, codecs, and basic dispatcher routing, but **zero coverage** for refresh behavior, event callbacks, subscription lifecycle, condition state machines, or spec-mandated edge cases.

**Recommended action plan**:
1. **BLOCKER-1**: Fix opnums 6, 10-18 in `IOPCEventServer` to match spec VTABLE order (add missing QueryEventCategories at 6, QueryEventAttributes at 10, shift GetConditionState/Enable/Disable/Ack from 10-15 to 12-17). Effort: 1 day.
2. **BLOCKER-2**: Fix `IOPCEventServer2` opnums 16-19 to 19-22 (account for inheritance). Effort: 2 hours.
3. **BLOCKER-3**: Add IFACE pointer out-param support to generator, implement `CreateEventSubscription` (opnum 4) and `CreateAreaBrowser` (opnum 18). Effort: 1 week (generator + test).
4. **HIGH-priority**: Implement deferred multi-out methods (`GetFilter`, `GetState`, `SetState`, `GetEnableStateByArea`, `GetEnableStateBySource`). Effort: 3 days.
5. **Test coverage**: Add integration tests #1-20 listed above, prioritizing opnum compliance (test #1), refresh behavior (test #4), and event callback delivery (test #7). Effort: 2 weeks.
